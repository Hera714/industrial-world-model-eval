# Week 6：BOPTEST 动作条件世界模型与控制评测协议

本周只评测 BOPTEST；IB 和简化二阶热工环境不纳入结果表。主案例为 `bestest_hydronic_heat_pump`，平台 v0.9.0，固定 commit `9b1610bf7a108826bb3d22c72bffd2d71d7bb0a9`。本地部署修改见 `deployment/boptest/`；FMU、资源 CSV、案例面积和 KPI 映射摘要见 `reports/week6/results/assets/manifest.json`。不把平台版本年份或仿真数据年份当作模型准确性的证据。

## 1. 状态、动作、输出与可见信息

建筑的完整物理状态不可直接得到。这里预测的是公开观测向量，不把它称为完整 Markov 状态。

| 类型 | 字段 | 模型外部单位与含义 |
| --- | --- | --- |
| 观测 | `reaTZon_y` | 区域操作温度，API K，转换为 °C；不能随意称为空气干球温度 |
| 观测 | `reaTSup_y`、`reaTRet_y` | 辐射供/回水温度，转换为 °C |
| 观测 | `reaQFloHea_y` | 地板向区域释放的热流，转换为 kW |
| 观测 | `reaPHeaPum_y`、`reaPFan_y`、`reaPPumEmi_y` | 三项电功率之和，转换为 kW，不能仅用热泵功率代表总电耗 |
| 动作 | `oveTSet_u` | 当前15分钟的区域温度设定值，API K，控制器使用 °C；实验边界18～24 °C |
| 激活 | `oveTSet_activate` | 1覆盖，0释放回案例内置控制；每次推进明确发送 |
| 外生 | `TDryBul`、`HGloHor` | 室外温度°C与总水平辐照W/m² |
| 已知日历 | 日/年周期正余弦 | 根据模拟时间计算，不包含未来室温 |
| 输出 | 下一观测向量 | 以上5个变换后的公开观测量 |
| 输出 | 本步总电耗 | 热泵、风机、水泵的15分钟积分能耗，kWh |

模型输入16个时间步（4小时）的相同信息。第 i 个历史 token 为“动作前观测、该步实际动作、该步外生信息”；最后一个 token 的动作在规划时替换为候选当前动作。预测目标为下一观测和当前到下一时刻的区间能耗。自由递推用模型预测观测更新历史，能耗作为成本输出，不当成要递推的建筑状态。

`models/boptest_dynamics.py` 提供共同的 `predict(history)` 与结构化 `predict_transition(history)`；GRU 每个历史窗口从零隐藏状态编码，不在窗口/候选间共享隐藏状态。Persistence、ARX、历史MLP、GRU输入字段一致。Persistence 的观测保持不变，步能耗用当前总电功率乘0.25小时，是明确标记的简单基线。

## 2. 采集、切分与补充协议

控制步长900秒，每块7天预热、1天动作历史上下文、2天有效采集。以完整时间块划分：8块训练、2块验证、8块测试/参考，共18块5184条转移。所有块的“预热+上下文+目标”时间范围均不重叠，训练/验证各有1536/384个有效一步目标。滑动窗口历史仅来自同一块。

动作策略为小时保持的随机合法设定值或预定分段日程；记录请求与实际生效值并核对，不把未生效请求当作动作标签。数据不从真实建筑采集，是物理模型驱动的公开仿真数据。

原始日历分组先于采集固定。天气元数据核查后发现 day172 有18.23%的有效时段温度超出训练范围，因此保留为日历变化案例，不称为纯ID。补充协议在 `week6_boptest_extensions.yaml`，依据天气元数据增加day292、day340，未根据模型误差筛选日期。主要参考日期为day160、292、340，温度均在训练支持范围内；这仅表示支持范围匹配，不保证所有变量的联合分布相同。

冷季保留日期day12、24属于季节分布变化，不是温度范围外推。暖季day196、208的超训练温度比例分别约5.73%、62.50%。逐块均值、范围和比例见 `open_loop/weather_support.csv`。严禁仅凭文件名 `ood_cold` 就宣称出现了范围外温度。

## 3. 训练与开环

标准化参数只用训练窗口拟合。ARX 用验证集选岭系数（0.01、1、100），MLP/GRU固定网络与学习率，验证集早停，最大120epoch、耐心15。三个训练种子42/43/44，训练权重与尺度随检查点保存。测试场景不重新拟合模型或标准化。

共同测试起点每4步选一个，所有起点支持20步，比较1、5、10、20步的逐变量末端MAE/RMSE，并保留完整20步自由/teacher-forced预测。温度°C、功率kW、步能耗kWh分别报告，不能直接平均成一个混合单位误差。

主要信息集采用“未来天气保持起点观测”，未来日历已知。`ideal_weather_reference`额外使用API的无误差天气预报，仅作理想信息对照；不得说成模型自己预测天气。Teacher forcing允许每步读取届时真实观测，仅用于一步诊断；free-running禁止未来状态回填。

噪声/缺失只作用于模型或控制器的观测，不改变FMU物理状态。开环温度噪声标准差0/0.1/0.3°C，三个温度通道独立扰动；缺失为起点供水温度传感器1/4步连续缺失，按最后有效值填补。自由递推不在后续恢复时偷读真实未来状态。闭环采用0.3°C噪声，或每24步连续缺失4步；两种故障分开运行，随机流独立且固定。

NaN/Inf、推理异常和绝对值超过1000的发散停止该窗口，保留此前预测与事件，后续为无效。负能耗、负电功率与温度启发边界属于物理警告，原始开环输出不修正。警告是轨迹级标签；每horizon同时报告有效比例和有效样本误差。缺失/失败不默默删掉。

## 4. MPC、评分与fallback

真实状态始终由BOPTEST推进。每步随机shooting候选256条、时域12步（3小时）、候选动作块保持4步，实际只执行第一个动作，每15分钟重规划。所有模型每步共享同一候选随机流和五条恒定候选。主实验模型权重、动作边界、预算、日程与初始历史均固定。

舒适上下界使用案例公开的日程，独立于可控设定值。阶段评测/规划代价一致：

$$
\ell_t=\left[\max(L_t-T_{t+1},0)+\max(T_{t+1}-U_t,0)\right]^2\Delta t
+E_t+0.02(u_t-u_{t-1})^2,\qquad\Delta t=0.25\text{ h}.
$$

这是有单位分项的加权示例评分，不是官方货币成本：舒适项°C²h、能耗kWh、动作变化项°C²。权重承担尺度换算意义。另报区间中心跟踪MAE、舒适违反步数比例、累计舒适偏差°C·h、实际电耗kWh和决策均值/P95耗时。

时间预算5秒，按每次批量模型预测前及规划结束检查，不能抢占单个阻塞调用。候选能耗负值、预测温度异常等无效轨迹被排除；所有候选无效、超时或异常时释放覆盖，交还案例内置控制，日志记录原因。没有优化求解器的硬可行性证书，不称为“求解器不可行”。fallback产生的实际温度、动作和能耗全部计入。

原生 `ener_tot` 为kWh/m²，面积192m²。区间能耗通过原生累计值差分乘面积得到；另用三个功率测点的原始积分独立核对。闭环前1天上下文不计入评分；保存上下文末与最终原生KPI。只允许对累计可加量取差，峰值/比率不能直接相减。原生KPI仍使用案例原有舒适标准。

目标OOD在同一参考日期把独立评分舒适上下界同时提高1°C，模型不变、天气和初态相同；它是控制任务变化，不是新的建筑方程。内置控制器仍按原日程运行，其表现作为明确基线，不谎称其也被重新设计。

## 5. 统计与预测—控制一致性

主要参考日期3个、每类季节保留日期2个、额外日历变化1个。各模型的训练种子不是新的物理episode。先按日期统计，再汇总训练种子和日期差异；bootstrap的单位为日期，不能重采样15分钟时间步。样本少，置信区间只作描述性参考，不作强显著性结论。

原生控制+8个模型实例，共72个clean回合；3参考日期×9控制实例×两种故障54回合；相同参考日期目标变化27回合，预定总数153。中断回合写partial和failure，不产生complete记录；全量验收检查每个预定身份。

散点横轴为独立固定动作数据的20步室温RMSE，纵轴为该模型MPC实际闭环成本。它们的动作分布不同，排序关联不是因果证据。必须检查动作、能耗预测、舒适偏差和fallback日志解释案例，不预设必定反转。

额外策略排序任务把各控制器实际执行的前20步动作冻结成计划，从同一初始历史自由预测；真实成本由同一BOPTEST轨迹前缀得到。评价方向一致率、无效计划比例及所选计划的真实regret。此任务评价固定动作计划，不等价于模拟反馈策略本身。

仿真与模型批量推理在同一WSL主机上并发，耗时是当前运行条件下的实测值，不是严格隔离的硬件性能基准。当前采用3个相同镜像的独立worker，测试实例互不共享建筑状态。

内置控制器使用FMU内部传感器，客户端故障不影响它；所以它是工程参照，不是同信息集的故障鲁棒性对手。发生fallback的系统是模型MPC与内置控制的混合系统。候选启发过滤为区域温度0～50°C、步电耗0～10kWh及数值有限性，不是所有隐藏物理状态的安全约束。
