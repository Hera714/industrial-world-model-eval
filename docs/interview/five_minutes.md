# 五分钟项目介绍

我研究的是动作条件世界模型是否真正能支持楼宇控制。项目以 BOPTEST 的 bestest_hydronic_heat_pump 案例为主平台，采集室温、供回水温度、热流、电功率、设定值及天气数据。每步 15 分钟；模型用 16 步历史预测下一公开观测和区间能耗。

这里的世界模型可以先理解成一个“预测器”：控制器问它，如果现在把温度设定值调高或调低，接下来楼宇可能怎样变化、需要多少电。模型必须把动作作为输入；如果只根据过去的温度画趋势线，就无法比较两个不同动作的后果。BOPTEST 提供基于物理建模的模拟案例，让我们能够在不操作真实设备的情况下做这些对照。

实验比较 Persistence、ARX、历史 MLP、残差 MLP 和 GRU。数据按完整时间块隔离训练、验证与测试。开环在固定动作计划下比较误差；闭环把各模型放进相同预算的 shooting MPC，让动作在模拟器中实际执行，记录能耗、舒适偏差、成本和 fallback。

Persistence 认为状态保持不变，是很简单的基线；ARX 用线性关系表示历史信息与动作；MLP 和 GRU 尝试从数据学习非线性关系。开环评测时，不同模型从相同历史出发，面对相同动作计划，我们观察单步和多步误差如何变化。闭环则更接近控制：MPC 生成许多候选动作序列，让模型预测每条序列的后果，选成本最低序列的第一个动作；动作在 BOPTEST 中执行，再读取新观测重新规划。

核心发现是预测与控制排序可能不同。例如 id_test_day340 中 Persistence 的离线室温 RMSE 约 0.667 °C，低于 mlp_seed43 的约 0.753 °C，但闭环成本约 382.97，高于后者的 124.44。它是配对观察，不能仅凭这组数证明原因。来源：`reports/week6/results/summary/prediction_control_counterexamples.csv`。

这个例子提醒我们，预测表里的第一名不一定能直接变成控制表里的第一名。一个可能的原因是：开环评测给模型固定动作，控制时模型还要帮助 MPC 区分不同动作的好坏；另外，误差出现在什么温度区间、成本如何加权、有没有触发后备动作，也可能影响结果。以上是需要结合轨迹进一步验证的解释，而不是仅凭一个案例确定的因果关系。

工程上将实验配置、模型哈希、原始轨迹、指标和失败上下文保存到独立目录，支持容器运行和批量恢复。Week8 的 Agent 负责配置建议与工具编排，指标由确定性代码计算。本地模型已完成真实 BOPTEST 端到端演示；隔离 CPU 容器在资产准备好后的一次计时为 92.96 秒。工具自主选择仍不稳定，在 20 条开发用例的严格首步评分为 7/20，执行门禁因此不可省略。

项目的边界也需要讲清楚。BOPTEST 虽然有物理模型，但仍然是仿真；案例和独立日期有限，模型只看到公开观测，并不是完整的建筑内部状态。Agent 的评测用例也参与过设计，不能作为独立泛化成绩。这个项目的价值是搭建一条可以追溯、可以复现、同时检查预测与控制的实验链路，而不是证明某个模型已经可以直接部署到真实楼宇。
