# 十分钟技术深挖

先介绍 BOPTEST 的预热、历史上下文与评分窗口：动作覆盖以摄氏度表示，经适配器转换为 API 的开尔文；实际执行值和覆盖状态都记录。服务端能耗是单位面积累计量，本案例按面积转换为区间 kWh。

实验划分的单位是完整时间块。训练、验证、测试采用不同时间块，避免相邻时刻的样本被拆到不同集合。每个时间块先进行预热，再提供历史上下文，之后才开始记录有效评分区间。模型训练时的标准化参数只由训练数据拟合；验证集用于选择参数，测试集用于最后评估。天气范围外与设定目标变化分别作为不同的分布外条件，不能把不同日期的结果说成同一天的随机干预。

再解释模型信息集：五个公开观测、当前动作、室外温度、太阳辐射和日/年周期组成 12 维，每个历史窗口 16 步；输出为下一步五观测及本间隔能耗。残差模型对前五维预测增量，能耗不是递推状态。GRU 每个窗口独立初始化。

与直接 MLP 的差别是，残差 MLP 让网络学习观测的变化量，再加回当前观测；这是一种输出参数化方式，并不自动保证物理正确。GRU 利用循环隐藏状态处理窗口内的历史，但评测时每个窗口重新初始化，不允许把上一个测试窗口的隐藏状态带到下一个窗口。Persistence 和 ARX 作为较简单的参照，帮助判断复杂模型是否真的带来收益。

开环 teacher forcing 可见下一步真实观测，自由递推使用模型自身预测；未来天气信息集需要单独标注。闭环统一候选数、时域、动作范围、目标和成本，MPC 失败释放到 embedded 控制；超时检查不能抢占单次阻塞调用。

两种预测模式回答的问题不同：teacher forcing 在每个时刻使用真实历史，检查模型一步预测能力；free running 从起点开始，把预测结果放回历史窗口，检查误差积累。开环主要天气条件将起点天气保持不变，另有理想天气条件单独报告，不能把后者说成实际部署中一定可用。第 20 步对应 5 小时，成本分析中的 MPC 时域为 12 步、即 3 小时，两个时间尺度不同。

闭环公平性通过相同日期、初始历史、动作边界、候选数量、规划时域和评分公式保证。每个模型的控制动作都在 BOPTEST 中执行，而不是在其自身预测中结算成绩。成本包含舒适偏离、能耗和动作变化项；它是实验权重下的评分，不是直接的电费。规则控制器或 embedded 控制器与模型控制器比较时，还要说明前者可能有不同的内部传感器信息。

以 `prediction_control_counterexamples.csv` 中 id_test_day340 的 persistence / mlp_seed43 反例解释预测—控制一致性；说明开环固定动作和闭环优化任务不同，不能据单点断言因果。最后解释检查点哈希、按 episode 汇总、批量进程隔离和真实服务测试；模拟器结果不等同真实建筑部署。

在这个案例中 Persistence 的五小时末端室温误差约 0.667 °C，低于 `mlp_seed43` 的约 0.753 °C，但闭环成本分别约为 382.97 和 124.44。要进一步分析原因，需要查看对应日期的动作、温度、能耗及 fallback 轨迹；不能仅凭散点图证明是哪个机制导致差异。统计时先在 episode 内汇总，再比较独立日期；多个模型种子和高度重叠的窗口不能冒充新的独立建筑实验。

可复现性方面，统一 Runner 在每个 run 保存配置、数据和检查点哈希、依赖及代码版本、逐步轨迹、指标与失败上下文。批量任务使用独立 testid，恢复时检查已完成结果和输入哈希；服务超时后不假定动作没有生效，避免盲目重试。当前仍有局限：修改后未提交的代码不能仅凭 commit 完全追溯；环境数据、FMU 和模型资产需要单独准备。

如涉及 Agent，说明结构化意图、工具白名单、确定性审核和 LangGraph 中断机制。本地模型真实运行与规则流程各有 6/6 合法用例通过运行和审核；工具由固定流程编排。自主首步选择严格评分仅 7/20，且这 20 条用例参与过设计，不能声称模型具有可靠的通用工具能力。自主循环已完成真实案例，前两次没有正常结束的轨迹也保留；人工审批的真实会话经用户批准后已完成并通过独立审核。
